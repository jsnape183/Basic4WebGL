# UI Audit — Basic4WebGL React Frontend

**Date:** 2026-05-21  
**Scope:** Phase 1 of 3 — deep understanding of the current React structure, features present in the UI, and proposals to feed into Phase 2 (architectural refactor).

---

## 1. What the App Is

A browser-based IDE for the softBASIC language. It lets a user:

- manage named **projects**, each owning one or more `.bas` source files and image assets;
- **edit** source code with syntax highlighting powered by Monaco Editor;
- **compile** the source via the Basic4WebGL transpiler (TypeScript, same repo);
- **run** the compiled output in a sandboxed iframe, with PixiJS powering the graphics layer;
- watch **console output** (including runtime errors) stream back from the iframe.

Everything persists to `localStorage` via redux-persist, so the app works offline and survives refreshes.

## 4. Pages

### 4.1 ProjectsPage (`/`)

Thin wrapper — renders `<ProjectList>`. No state of its own.

### 4.2 EditPage (`/projects/:id/edit`)

The core IDE view. Owns the run/stop workflow.

**Local state:** `isRunning: boolean` (toggles the Preview pane into view)

**Redux reads:** `projects.items`, `files.byId`, `files.selectedFileId`, `ui.transpiled`

**Redux writes:** `clearLogs`, `addLog`, `setTranspiled`, `updateFile`

**Layout:**
```
┌─────────────────────────────────────────────────────┐
│ Header: project name  │  [Run] / [Stop] button       │
├──────────────┬──────────────────────┬────────────────┤
│  TreePanel   │   Monaco Editor      │  Preview pane  │
│  (w-64)      │   (flex-1)           │  (flex-1)      │
│              │                      │  (only when    │
│              │                      │   isRunning)   │
└──────────────┴──────────────────────┴────────────────┘
```

**Run flow (happy path):**
1. Dispatch `clearLogs`
2. Build a `CompilerProject` from Redux state (all `.bas` files for the project)
3. Call `Basic4WebGL.transpile(project)` → `CompileResult`
4. On success: dispatch `addLog('compiled successfully')`, dispatch `setTranspiled(code)`, `setIsRunning(true)`
5. On error: dispatch each diagnostic as an error log, dispatch `setTranspiled('')`, `setIsRunning(true)` — **note:** isRunning is set true even on failure, which shows the (empty) preview pane

## 5. Components

### Editor (`SBEditor`)

Monaco Editor wrapper. Registers a custom `"softBasic"` language with tokenization rules on first mount (`languageLoaded` local flag prevents re-registration). Passes change events up via `onChange` prop.

### Preview

Composite pane. Shown only when `isRunning` is true. Renders:
- **Runner** — iframe with `srcDoc` built from `bootstrapper.html` + injected transpiled code + PixiJS init scripts
- **Console** — log panel; also installs a `window.message` event listener to capture `console.log` and `runtimeError` messages sent from the iframe via `postMessage`

### Runner

Builds the iframe `srcDoc` string by concatenating several helper scripts (`softBasicGFX.js`, `softAssetManager.js`, `softSpriteManager.js`, `pixiInit.js`) with the transpiled source. Sandboxed with `allow-scripts allow-same-origin`.

### Console

Dual role: (1) renders the `logs` array from Redux; (2) installs a side-effectful `window.addEventListener('message', ...)` handler. Colour-codes log entries by type.

### ProjectList

Grid of project cards. Each card has a "link to edit" and a "remove" button. Has an "Add Project" button that dispatches `createProjectWithMainFile`.

### TreePanel / FileTree / AssetTree

Sidebar tabs. FileTree lists files for the current project and dispatches `selectFile` on click. AssetTree lists images and handles uploads (reads file as base64 DataURL, writes to both Redux and localStorage independently).

### ModalWithInput

Simple toggle modal (no React Portal). A single controlled text input with Save/Close buttons.

  logs: Array<{ type: LogItemType; text: string }>

**Note:** `selectedFileId` is on `IFilesState` but per-project selection is tracked again in `UIState.selectedFileByProject`. The two are not always in sync.

## 7. Data Flow

```
User clicks Run
  │
  ▼
EditPage.handleRun()
  ├─ dispatch clearLogs()
  ├─ assemble CompilerProject from Redux (files.byId filtered by project)
  ├─ Basic4WebGL.transpile(project) → CompileResult
  │
  ├─ [error] dispatch addLog(diagnostic) × N  ──► uiSlice.logs
  │          dispatch setTranspiled('')
  │
  └─ [success] dispatch addLog('compiled')     ──► uiSlice.logs
               dispatch setTranspiled(code)    ──► uiSlice.transpiled
               setIsRunning(true)              ──► local state → Preview visible

Runner receives transpiled prop
  └─ builds srcDoc string (bootstrapper + helpers + code)
     └─ iframe executes → PixiJS starts

iframe code calls console.log(msg)
  └─ postMessage({ type: 'log', … }) to parent

Console window.message handler
  └─ dispatch addLog(msg) ──► uiSlice.logs ──► re-render Console list
```

## 8. Current Issues

The issues below are grouped by severity. They are the primary inputs into the Phase 2 refactor scope.

### Critical (bugs / crashes)

| # | Location | Issue |
|---|---|---|
| C1 | `Console.tsx` | `throw Error(e.data.message)` executed inside an event listener after dispatching `addLog`. This is an unhandled throw in a non-React call stack — it crashes the tab, not React. |
| C2 | `FileTree/index.tsx` | `handleFileSelected()` called directly in the component body (lines 27–29) on every render. Can cause an infinite dispatch loop if selecting a file triggers a re-render. Should live in a `useEffect`. |

### High (correctness / security)

| # | Location | Issue |
|---|---|---|
| H1 | `Console.tsx` | `TRUSTED_ORIGINS` check is commented out. The iframe `postMessage` listener accepts messages from **any origin**, which is a security risk if any other page is embedded alongside the app. |
| H2 | `EditPage.tsx` | `setIsRunning(true)` is set even when compilation fails. The Preview pane opens but displays nothing. Should stay hidden or show a dedicated error state. |
| H3 | `AssetTree/index.tsx` | Assets are written to both Redux (which persists via redux-persist) and to a separate `useLocalStorage` call. There is no reconciliation between them — they can diverge after a hard refresh. |
| H4 | `IFilesState.selectedFileId` vs `UIState.selectedFileByProject` | Two sources of truth for the selected file, one global and one per-project. Callers use whichever is convenient, leading to inconsistent selection when switching projects. |

### Medium (quality / maintainability)

| # | Location | Issue |
|---|---|---|
| M1 | `features/` | `deleteProjectWithMainFile` thunk is defined but never imported or called anywhere. Projects are removed but their files are not cleaned up. |
| M2 | `ModalWithInput.tsx` | Modal uses a fixed overlay in the DOM rather than a React Portal. Z-index layering will break if nested in any stacking context. |
| M3 | `components/` | No React Error Boundary anywhere. A crash in `Editor`, `Preview`, or `Runner` tears down the whole page. |
| M4 | `EditPage.tsx` | `buildProject` (the assembled `CompilerProject`) is rebuilt inline on every run. No memoisation — irrelevant if compile is fast, but signals the lack of separation between "assemble inputs" and "run compiler". |
| M5 | Types | `IFile` (slice) and `SBFileProps` (Editor prop type) represent the same concept under different names. |
| M6 | `uiSlice.ts` | `transpiled` (the full JS blob, potentially hundreds of KB) is stored in Redux and serialised to localStorage on every compile. It does not need to persist across sessions. |

### Low (accessibility / UX)

| # | Location | Issue |
|---|---|---|
| L1 | All interactive elements | No `aria-label` attributes on icon buttons; no keyboard navigation in FileTree; modal lacks focus trapping and `aria-modal`. |
| L2 | FileTree | No way to delete a file from the UI. The Redux action exists but is not surfaced. |
| L3 | EditPage | No unsaved-changes indicator. All edits auto-save to Redux/localStorage, but there is no visual confirmation. |
| L4 | Editor | No undo/redo beyond Monaco's internal single-file undo stack. Switching files and switching back resets the in-editor history. |

## 9. Architecture Observations

### What works well

- Redux Toolkit is used cleanly — slices are focused, action names are clear.
- The iframe sandbox + `postMessage` pattern for running untrusted code is correct in principle.
- Monaco integration is minimal and self-contained.
- Tailwind keeps styling co-located and avoids a separate stylesheet layer.
- `redux-persist` gives localStorage sync for free.

### Structural tensions

**1. UI state lives in the wrong slice.**  
`transpiled` and `logs` belong to the current editing _session_, not the persisted application state. They should not survive a page refresh, and serialising a large JS blob to localStorage on every compile is wasteful. A separate, non-persisted session slice (or local component state) would be cleaner.

**2. File selection is split across two slices.**  
`IFilesState.selectedFileId` is a single global cursor. `UIState.selectedFileByProject` is the per-project version. The code uses both depending on where it was written. One should be removed.

**3. Assets have two storage mechanisms.**  
Redux + redux-persist already handles localStorage. The additional `useLocalStorage` write in `AssetTree` is redundant and creates a divergence risk.

**4. `EditPage` is doing too much.**  
It owns routing guards, layout, compiler invocation, file assembly, log dispatch, and run/stop control. The compiler-invocation logic especially would be cleaner in a custom hook or a thunk.

**5. `Console` has dual responsibility.**  
It both listens to window events (side effect) and renders logs. The listener belongs in a hook or in the `Preview` parent, not inside a display component.

**6. No component composition boundary between layout and features.**  
`EditPage` directly renders `TreePanel`, `Editor`, and `Preview` as siblings. There is no layout shell that could be reused or restyled without touching feature logic.

## 10. Proposals for Phase 2 (Architectural Refactor)

The proposals below are deliberately structural — they are about boundaries and responsibilities, not visual redesign. Phase 3 handles the look.

### P1 — Split persisted state from session state

Create a `sessionSlice` (not persisted) to hold `transpiled`, `logs`, and `isRunning`. Remove `transpiled` and `logs` from `uiSlice`. This reduces localStorage churn and makes the conceptual boundary explicit.

### P2 — Unify file selection

Pick one home: `UIState.selectedFileByProject: Record<string, string>` is the right model (per-project). Remove `IFilesState.selectedFileId`. Update all consumers to read from the UI slice.

### P3 — Remove redundant asset localStorage writes

Delete `useLocalStorage` from `AssetTree`. Trust `redux-persist` for asset persistence. If large base64 blobs cause localStorage quota issues, that should be addressed at the `redux-persist` storage adapter level (e.g., `localforage` or IndexedDB).

### P4 — Extract compiler invocation into a hook

Create `useCompiler(projectId)` returning `{ run, stop, isRunning }`. This hook assembles the `CompilerProject`, calls `Basic4WebGL.transpile`, and dispatches to `sessionSlice`. `EditPage` becomes a thin layout component.

### P5 — Extract iframe message handling into a hook

Create `useRunnerMessages()` returning nothing (or a cleanup). It installs the `window.message` listener, validates origins, and dispatches to `sessionSlice`. `Console` becomes a pure display component.

### P6 — Add a `ProjectShell` layout component

A wrapper that owns the three-pane layout (sidebar / editor / preview) and can be composed by `EditPage` without mixing layout and logic. Makes Phase 3 restyling surgical.

### P7 — Add React Error Boundaries

At minimum: one around `Editor`, one around `Preview`. Optionally a root-level fallback.

### P8 — Fix the three bugs before refactoring

C1 (throw in listener), C2 (side effect in render), H1 (unchecked postMessage origin) should be fixed as a precursor to refactoring so that the refactored code does not inherit them.

### P9 — Reconcile the `IFile` / `SBFileProps` type duplication

Pick one name (suggest `ProjectFile` to align with the compiler's existing type) and use it everywhere.

### P10 — Move `createProjectWithMainFile` / `deleteProjectWithMainFile` to projectsSlice

The thunks live in `constants/projectLib.ts` which is an unusual location. Moving them into `features/projects/projectsSlice.ts` (as `extraReducers` or async thunks) keeps feature logic with its slice.
